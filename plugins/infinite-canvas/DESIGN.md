# 无限画布插件设计

## 目标

无限画布是 VideoFree Studio 的应用级自动化编排器。用户把已安装的普通生成插件能力、自动化动作和画布专属节点拖入画布，连接类型化端口，保存为可分享 JSON，并按前向依赖图执行。它面向稳定的产品能力，不暴露 ComfyUI 原始节点编号和模型路径。

## 边界

- 本插件拥有画布 UI、工作流 JSON、连线校验、DAG 调度、执行状态和项目级持久化。
- 框架拥有普通能力、插件动作、画布专属节点的发现/执行 API、项目鉴权和插件文档存储。
- 本插件在浏览器内把现有生成能力、后处理能力和资源级后处理动作适配为节点，不修改也不导入其他插件代码。
- 带 `application` 或 `project_tool` 的应用/项目工具整体排除；`workspace` 业务动作不进入画布。画布只显示生成插件、后处理插件和独立画布扩展。
- `plugins/canvas-nodes/<package-id>/` 只放条件、特殊数据变换、项目资源读取等独立画布扩展；通用智能体由本插件内置，这些扩展节点不注册为普通插件。
- 不直接访问 SQLite、ComfyUI、其他插件源码或项目绝对路径。
- 数据边与前向控制边保持有向无环；循环只能由“失败”或“继续”端口显式回连，并且必须沿数据路径重新到达对应条件节点。不实现并行调度、远程协同、多租户或多 ComfyUI 调度。

## 界面

- 左侧：分为“基础节点”“智能节点”“生成插件”“后处理插件”和“画布扩展”。基础节点再按输入、媒体、数据、流程控制、输出与预览分组；智能节点提供一个由技能和系统角色决定行为的通用智能体。所有组默认收起并支持搜索、拖放。
- 平台动作节点复用工作台的声明式 UI。`target_size/dimensions` 显示为一个分辨率档位选择器，默认使用插件 `presets` 第一项；运行时按来源任务画幅和插件对齐规则换算宽高，不暴露底层 `width`、`height`。
- 中间：主工作区，支持平移、缩放、节点移动、端口连线和外部媒体文件直接拖入。
- 节点卡片直接完整显示插件声明的全部参数、媒体端口和项目资源预览，不设置“更多参数”折叠层。
- 右侧属性栏不常驻。运行检查失败时显示可点击的问题面板，并同步标红对应节点、端口或连线；点击问题自动定位节点。
- 顶部：工作流以标签展示，“+”直接新建浏览器草稿；另有项目资源选择、本地文件导入、保存、JSON 导入导出、校验、运行和停止。未保存草稿按项目暂存在浏览器，首次保存时才输入名称并写入项目。
- 右下角：减号、可直接输入的缩放百分比和加号；支持 25%–200%，滚轮缩放与“适应画布”保持同步。

## 工作流格式

```json
{
  "schema_version": 1,
  "kind": "videofree.infinite-canvas",
  "id": "workflow-example1",
  "name": "示例工作流",
  "nodes": [{
    "id": "node-example1",
    "type": "videofree.capability.image.example.generate",
    "position": {"x": 120, "y": 160},
    "config": {},
    "values": {}
  }],
  "edges": [{
    "id": "edge-example1",
    "kind": "data",
    "from": {"node": "node-example1", "port": "output"},
    "to": {"node": "node-example2", "port": "input"}
  }],
  "viewport": {"x": 0, "y": 0, "zoom": 1}
}
```

格式只保存稳定 ID、端口值和坐标，不保存翻译文字、绝对路径、运行结果或节点声明副本。稳定类型前缀为：

- `videofree.capability.<capability-id>`：普通插件生成或后处理能力；
- `videofree.action.<action-id>`：普通插件的自动化动作；
- `canvas.<package-id>.<node-id>`：画布专属节点。
- `videofree.resource.<media-kind>`：插件内部的项目资源输入节点；导出的工作流仍只含项目资源相对句柄。
- `videofree.agent.generic`：通用智能体；具体行为由 `skill_id`、系统角色和任务提示词决定。
- `videofree.control.llm-condition`：通用 LLM 条件节点；成功时原样透传任意类型产物，失败时发出控制信号。
- `videofree.control.count`：可选次数控制节点；由用户设置循环上限，并分别输出“继续”和“结束”。

导入缺失节点插件的工作流仍可查看和保存，但校验与执行会阻止并列出缺失节点。

## 节点连接契约

画布根据端口声明判断连接，不根据节点名称猜测。基础端口继续支持 `type`、`required` 和旧版 `multiple`；应用宿主还统一识别以下增强字段：

```json
{
  "id": "references",
  "type": "asset",
  "accepts": ["image", "video"],
  "semantic": ["reference_image", "reference_video"],
  "cardinality": "many",
  "min_items": 1,
  "max_items": 4,
  "required": true
}
```

- `accepts` 是输入允许的来源类型；声明后取代旧版宽松兼容规则。
- `semantic` 描述输出业务含义，输入可用 `accepts_semantic` 进一步限制用途。
- `cardinality` 为 `one` 或 `many`；`multiple: true` 向后兼容为 `many`。
- `min_items` / `max_items` 约束入线或手动值数量。
- 不做隐式类型转换；需要转换时必须连接显式转换节点。

当前框架画布节点发现接口只接受和透传基础字段，因此第三方 `canvas-nodes` 包暂时不能依赖增强字段。无限画布自身适配出的平台能力、动作和内置预览节点会使用完整契约；第三方节点继续使用基础类型兼容规则。

插件内部节点使用统一运行契约。`executor` 选择已注册执行器，不再由主调度器按节点名称或端口名分支；新增执行类别只需注册一个处理器。动态透传输出通过 `passthrough_from` 绑定输入，输出类型会沿实际连线解析：

```json
{
  "executor": "condition",
  "inputs": [{"id": "payload", "type": "any", "type_var": "T"}],
  "outputs": [{
    "id": "success",
    "type": "any",
    "type_var": "T",
    "passthrough_from": "payload"
  }]
}
```

控制流使用版本化 `flow` 契约，而不是依赖“失败、继续、结束”等显示名称。当前正式支持：

- `retry_decision`：声明 `payload_input`、`success_output`、`retry_output`；
- `retry_counter`：声明 `trigger_input`、`continue_output`、`exhausted_output`、`limit_config`；
- 控制输出用 `flow_mode: forward | retry | loop` 决定前向、适配或循环连线。

运行前会校验执行器是否存在、端口 ID 是否重复、透传来源、控制端口类型、Flow 版本及所有 Flow 字段引用。显示名称和翻译不参与执行逻辑。

无限画布自带图片、视频、声音和数据预览节点。预览节点是正式画布节点，接收并透传上游结果，不修改生成数据，也不调用框架外接口。
上游节点完成后，预览会直接读取该节点的已完成输出并立即刷新，不等待无关分支或整个工作流结束。

本地图片、视频和音频加载节点允许直接从电脑选择文件。为保证工作流保存、重启和生成时仍然有效，选择后的文件通过插件现有导入动作归档到当前项目资源库，节点只保存项目相对素材句柄，不保存浏览器临时路径或绝对路径。

## 连线与执行

1. 只允许输出端口连接输入端口，同一对端口不能重复连接。拖线期间兼容输入显示绿色，不兼容输入显示红色；释放到空白处会给出明确提示。
2. 优先检查 `accepts` 和 `accepts_semantic`；未声明时使用同类型、媒体与音频兼容规则。不兼容连接在创建时拒绝，导入 JSON 中已有的坏连接在运行前拒绝。
3. `cardinality: one` 只保留一条入线；`many` 按连线顺序组装数组并检查数量上下限。
4. 保存时插件后端检查结构、大小、引用、重复边和环路；运行前浏览器结合实时节点目录检查节点/连线 ID、端口、类型、语义、数量、必填值、项目素材归属、能力可用性及 JSON Schema 参数约束。
5. 普通数据边的 `kind` 为 `data` 并按拓扑顺序执行。能力节点用统一生成接口直接提交并轮询任务；动作节点用统一动作接口执行，资源动作从上游 `job` 端口取得 `source_job_id`；画布专属节点用其专用执行接口。
6. 能力节点固定使用 `prompt_processing: direct`。需要导演协作时应在进入画布前完成确认；画布运行不能停在交互式问答状态。
7. 每个节点执行前验证解析后的动态输入，执行后验证所有被下游使用的输出是否存在且类型正确。失败后停止调度，当前节点标红、下游标记跳过，已完成节点结果保留以便诊断；重新运行从头开始。
8. “停止”阻止继续调度，但无法中断已经提交的单次任务；界面会明确显示正在等待当前节点结束。
9. 前向控制边使用 `kind: control`，循环回边使用 `kind: loop`。连线种类由输出端口 `flow_mode` 和目标 Flow 契约决定。保存校验和运行校验都把循环回边排除在普通拓扑环路检查之外，但会验证重做目标确实能沿数据边回到判断节点。

## 智能体与条件分支

- 画布只提供一个通用智能体节点。实例通过插件内 `nodes/agent/skills/<skill-id>/` 选择技能，并在同一个“角色与任务”文本框说明它是谁、要做什么；不再分别暴露指令、上下文、数据、系统角色等重复输入。
- 默认使用平台系统 LLM，此时只显示技能、LLM 来源和“角色与任务”。温度、Token 上限、超时和结构修复策略均由插件预设，不向普通用户暴露。
- 选择“自定义 API”后才显示 OpenAI 兼容 URL、API Key 和模型。按产品要求，自定义 Key 会原样保存在浏览器草稿、项目工作流和导出的 JSON；输入框仅做视觉遮蔽。工作流文件应按密钥文件保护，不应公开分享。
- 智能体只向画布公开文本和结构化结果输出。图片、视频和音频从当前项目素材句柄安全读取；不接受任意本地绝对路径。每次最多接收 8 项、媒体总大小不超过 20 MB；路径不存在、不是普通文件、类型不支持或读取失败时会明确拒绝执行，不会静默忽略素材。
- “LLM 条件判断”把“原始产物”和“判断文本”分开接入。“判断规则”固定使用系统 LLM；内部模型协议只接受 0/1，并在格式异常时修复一次，但 UI 只显示“成功/失败”。
- 判断成功时，“成功”端口保持原始产物的类型和值，因此图片、视频、音频、任务或 JSON 都能继续传给相同类型的下游；判断文本不会替换产物。
- “失败”可用橙色虚线 `kind: loop` 直接回连一个重做目标。未接次数控制时会持续重做，直到判断成功或用户点击“停止”，插件不会暗设次数上限。
- 需要限制次数时，把“失败”接到“次数控制”的“触发”，再把“继续”回连重做目标；“最大循环次数”只计算重做，不包含首次执行。达到用户设置的重做次数后仍未成功，“结束”输出前向控制信号，可连接预览、通知或其他失败处理节点。
- 次数控制不是条件节点的隐藏参数，是否使用及上限都明确保存在工作流 JSON 中。条件失败到次数控制、次数控制结束到下游为 `kind: control`；条件失败直连重做目标、次数控制继续回连重做目标为 `kind: loop`。

## 持久化与冲突

- 未正式保存的工作流和对已保存工作流的本地修改按项目写入浏览器 `localStorage`，最多保留最近 12 个草稿；点击标签可无确认切换，首次保存弹框输入名称。
- 数据通过 `infinite-canvas.*` 插件动作保存到当前项目的插件文档存储。
- `revision` 使用乐观并发控制；冲突时保留浏览器草稿并要求重新载入。
- 删除动作不向自动化/MCP 开放。
- 单份工作流最多 500 个节点、2000 条边和 2 MB JSON。

## 可分享工作流文件

- `work/examples/` 是插件源码随附的示例目录，里面的每份 `.json` 都是完整的
  `videofree.infinite-canvas` 工作流，可以复制给其他人或直接拖入画布。
- 画布只接受一次拖入一个工作流 JSON；JSON 不能与媒体文件混拖。导入前会检查
  schema、节点/边的 ID、引用、数量和视口，导入后会生成新的工作流 ID，不覆盖当前工作流。
- 缺少插件节点的工作流仍可载入查看，但校验和运行会明确提示缺失节点。
- 用户创建和保存的工作流不写入插件源码目录，而是按当前项目隔离保存到运行时插件
  `work/` 目录；这样复制插件不会携带其他项目的数据，也不会把运行数据提交到源码仓库。
- 导出的 JSON 可能包含自定义 API Key。分享前必须手工清除密钥。

## 扩展

新增普通生成能力或资源级后处理动作时无需开发画布适配器，重启后会自动进入对应插件分区。项目管理、AI 进度等应用/项目工具不会进入画布。只有普通插件协议无法表达的条件、资源读取和数据变换能力，才开发独立画布节点包。宿主只读取稳定声明和调用统一 API，不因新增具体模型而修改。

生成能力和资源动作的“任务、产物、媒体结果”端口是 VideoFree Studio 统一任务返回契约的标准适配，不按模型名称硬编码。画布扩展节点的输出完全来自节点目录声明。内置输入、预览、智能体和控制节点属于本应用插件，其端口在本插件的节点声明中维护。

项目资源通过框架 `resourcePicker` 选择。外部文件拖入先调用网关上传，再调用本插件 `import-asset` 动作复制到项目资源库；工作流保存 `path` 等项目相对句柄，不保留临时上传 ID。浏览器拖入其他网页 URL 不作为支持的输入方式。
